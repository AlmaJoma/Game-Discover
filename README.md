# Game Discover
#### Video Demo:  https://www.youtube.com/watch?v=3lN0uQWX__0
#### Description:
The project, Game Discover, is a web app that, alongside the use of the RAWG database and plenty of libraries, has the purpose of using the answers of a simple questionnaire to create a profile and filter through the database to find the top 15 most compatible games, with the idea of discovering something new to play. The idea came from personal experience since I often find myself searching for a new experience to avoid going back to stuff I’ve already played, and for the task being making something of interest or to solve a problem, in this case wanting to do both.

“app.py” contains the main program; it makes everything work. It renders the HTML templates and handles the translation so the pages are available in two different languages (English and Spanish). The translation system uses cookies to remember the user's language preference. It creates the cache to make the site itself work and look better. The cache is important because constantly requesting the same data from RAWG would slow everything down and potentially hit rate limits. It contains the value of each different filter, from dates, to playtime, to tags, to genres. These filters are stored in dictionaries that map user choices to actual RAWG API parameters, for example, choosing "fast-paced" adds tags like "Fast-Paced" and "Action" to the search. The file handles the database requests to fetch games, exclude DLCs or special editions in the results, create the user profile based on the answers, and then search among the fetched games to create the top 15 games with the most value based on the answers and the games inputted in the search box. It also handles all the functionality of the search box in “test.html” including the real-time search that shows results as you type. Creating the algorithm for the profiling and filters was really hard; it ended up being more complicated than I initially expected. The algorithm works in stages: first it builds a profile from the games you've played by analyzing their genres, tags, and other metadata. Then it combines that with your questionnaire answers to create a complete picture of what you like. After that, it searches the RAWG database using parallel requests (so it's faster) to gather candidate games, and finally it ranks them based on how well they match your profile. I had to use AI as an aid to make it work how I intended it to, especially for the vector mathematics and similarity calculations that I'm not really that familiar with and the handling of the database, alongside creating the possibility to change languages. A big issue was that the algorithm kept recommending the same popular games to everyone. I added penalties for games that have been added to too many RAWG collections, which helps bring up more interesting, less obvious recommendations. But I had to be careful not to make the penalty too strong, or else only obscure games would show up. Another big issue was finding the most common and appropriate tags, since RAWG has a massive amount of them.

“index.html” contains the main page that leads to the test, with an image at the center for decoration and the button to access the test itself. There is not much to be said about it, besides the fact that I changed the design of the button a lot and I'm still not satisfied with it.

“layout.html” is the layout of all of the other HTML files. It contains the language switch button that lets users toggle between English and Spanish, the footer with the necessary information (the copyright of the elements I used, since some of the UI components were adapted from open source examples), and the overall design of the page (background, logo, button styles, and footer). The logo at the top also works as a home button, you can click it from anywhere to go back to the main page.

“result.html” is the one that displays the information after all of the processes made after the completion of the test. It shows the initial three cards and a "more" button that displays the rest of the games. I decided to only show three games at first because I didn't want to overwhelm people with too many choices right away. Each game card includes the cover image (or a placeholder if there isn't one available), the title, genres, rating, and release date.

“test.html” contains the test itself, with every question and answer containing specific values that match the desired filter. Finding appropriate questions was one of the hardest tasks, besides dealing with the profiling and filters, since I didn't want them to be too complicated or too specific, and I wanted a more general approach for better accessibility, and to avoid using technical gaming terms that might confuse casual players. The questions cover platform, game age, playtime, whether you prefer solo or multiplayer, pace, story elements, what makes games fun for you, exploration style, what brings you joy in games, visual style preferences, and a final "phrase" question that tries to capture your overall gaming motivation. At the end of the test, there is a search box that the user can use to add games they have previously played, with the option of clearing the selected games under it. As you type in the search box, it queries the RAWG database and shows results with cover images. Clicking a game adds it to your profile, and it shows up as a tag below the search box that you can click to remove. Right at the bottom, just above the footer, there's the button that submits the whole questionnaire and the games inside the search box. When you submit, everything gets processed and you're taken to the results page.
“styles.css” contains the values and the whole design of the elements inside the page, from the background, fonts, color, and size of the text, to the design of the footer, buttons, and cards, and even accommodations for devices other than a PC, so it looks good on every platform. As mentioned earlier, the button at “index.html”, the radio button and the background come from open source examples, the rest has been tweaked, created, and modified by me, with also some help of AI in some cases.
### Enviroment variables:
Since this project uses the RAWG database, to use it properly a RAWG API key is needed, then create a '.env' file in the project's folder with this content:

API_KEY=rawg_api_key_here
